# x86_64 port — inventory, measurements, what shrinks

Host is x86_64 Linux; guests are `x86_64-apple-macos` Mach-O. This VM can
build those guests with the pinned clang-18 + ld64.lld-18 toolchain and run
them under the ported loader natively. Arm64 stays a first-class target:
every `#ifdef` leaves the arm64 object byte-identical where the shared file
had to change.

Baselines in `tests/expected/` were recorded on Darwin/arm64. They are not
touched. Genuinely arch-dependent outputs are marked `NEEDS_DARWIN_X86_BASELINE`
for the operator to re-record on macOS under Rosetta 2 into
`tests/expected-x86_64/`.

## 2. What shrinks vs what carries

**Shrinks (x86_64 SysV is shared Darwin ↔ Linux):**

- Variadic calling convention: Darwin x86_64 `va_list` is the 24-byte SysV struct, same as glibc. The Darwin-compiled printf formatter still runs (compiled for the guest). Do not delete it.
- No pointer authentication / arm64e.
- `__sincos_stret` two-double struct return: the C compiler handles xmm0/xmm1.
- malloc_type "wrong register" was an argument-*order* bug, not an arch-register shim.

**Carries (OS-level — existing translation tables stay authoritative):**

- errno, O_*, CLOCK_*, signals, poll flags, MAP_ANON, sysconf names, xattr flag rotation, pthread mutex type swap.
- Darwin `struct stat` 144, dirent 1048, sigaction 16, utsname 1280.
- `$INODE64` symbol variants: x86_64 Darwin uses them; libSystem already exports `_stat$INODE64`.
- `__DARWIN_ONLY_UNIX_CONFORMANCE` is 1 on MacOSX x86_64 (no `$UNIX2003`). `__DARWIN_ONLY_64_BIT_INO_T` is 0.

**Must re-measure (host glibc layout differs on this x86_64 VM, 2026-09-02):**

| type | aarch64 (pinned) | x86_64 (measured here) |

| `FTSENT` | 120, `fts_level@92`, `fts_info@94` | **120**, `fts_level@96`, `fts_info@98`, `fts_statp@104`, `fts_name@112` |
| `FTS` | 72 | 72 (same offsets) |

| `jmp_buf` / `sigjmp_buf` | 312 | **200** |

## 3. Shared files that must change (arm64 path kept)

Every `#ifdef` leaves the arm64 compile of that file producing the same
bytes as before for the arm64-only regions. Files that gain an extra
architecture branch:

- `src/{macho.h,image.c,main.c,tlv.c,tlv_asm.S,crash.c}`
  (`src/map.c` was inspected: 47-bit isa-mask / VA-ceiling is host-neutral and was not edited)

  (`darwin/src/mach.c` uses `MR_DARWIN_PAGE` and did not need its own `#ifdef`)

- `sdk/MANIFEST.tsv` + staged `sdk/usr/include/{i386,mach/i386,libkern/i386}/**`, `fts.h`, `sys/uio.h`

```
denominators: matching 68/71 built,  68/71 run,  68/71 manifest
```

**REFUSED:** none. `exit_raw` / `exit_unixthread` assemble from
`tests/src/exit_raw_x86_64.s` and `tests/src/exit_unixthread_x86_64.s`
(beside the arm64 `.s`, not instead). ld64.lld-18 has no `-static`, so
`exit_unixthread` is linked as LC_MAIN then rewritten to LC_UNIXTHREAD by
`pack_macho.py unixthread`. The `cache_layout` family is built the same way
as on Darwin; `pack_macho.py` rewrites x86_64 RIP-relative disp32 when it
moves DATA (keeping the original TEXT-to-DATA distance would make `--sparse`
unrepresentable). A relocation shape the decoder does not handle is a named
`CANNOT_*`, never a silently broken image.

Historical refusals (closed):

| id | was |
|---|---|
| `exit_raw` | `CANNOT_ASSEMBLE_X86` — `tests/src/exit_raw.s` is arm64 |
| `exit_unixthread` | `CANNOT_ASSEMBLE_X86` — same; LC_UNIXTHREAD x86_64 needs a distinct `.s` beside, not instead |
| `cache_layout*` (six) | `CANNOT_BUILD_X86` — no builder case |

`exit_raw` is the permanent XFAIL (raw Darwin `syscall`; the loader diagnoses
it, it does not emulate it). `exit_unixthread` is NO-ORACLE (macOS SIGKILLs
static executables). Five of six `cache_layout` rows MATCH (Linux-graded; no
Darwin oracle). `cache_layout_oversize` MATCHES a reviewed x86_64 expectation
in `tests/expected-x86_64/` (a loader diagnostic with no Darwin twin on either
arch — the manifest marks it `norun`, so there was never a Rosetta baseline to
record): same diagnostic shape, 4 KiB x86 packed layout vs 16 KiB arm64
(`offset 8192+153 … 8344 bytes` vs `16384+457 … 16840`), exit 70.

The eight arch-dependent fixtures recorded into `tests/expected-x86_64/`
MATCH that baseline (exact bytes; no arch mask). `mach` now tests
`vm_page_size` alignment, which Darwin promises on both arches.

`isa_mask` MATCHED: the PIE loader lands above `__PAGEZERO` and below 2^47.

### SysV `%al` (measured, then fixed)

glibc `snprintf` is variadic. The historic non-variadic prototype is safe on
aarch64 (the callee always spills). On x86_64, SysV requires `%al` = XMM-arg
count; a Darwin-compiled non-variadic call leaves `%al` as leftover, so the
`floats=` line of `varargs` was wrong ~10–30% of the time (argument shift /
garbage). `mr_snprintf_d` (x86_64 only) sets `%al=1` before the call. After the
fix: 20/20 chained + 20/20 classic. Arm64 still calls `glibc_snprintf_d`
directly.

### `$INODE64` dirent/fts

x86_64 Darwin headers emit `_opendir$INODE64`, `_fts_open$INODE64`, etc.
(`__DARWIN_ONLY_64_BIT_INO_T==0`). Aliases are `#ifdef __x86_64__` so the arm64
dylib does not grow extra exports. `_stat$INODE64` was already present for both.

## 5. Phase 2 — real apps (this PR is not the finish line)

Definition of done is running real apps under the ported loader, not only
difftest fixtures. Phase 1 (inventory + core port + fixture scoreboard) stays
as scoped above. Phase 2 is a target-triple retarget of the proven guest
stacks, with arm64 outputs left untouched beside the x86_64 trees.

### 5.1 Script retarget

`full/scripts/guest_arch.inc` (macos15.0, not machorun's macos11) picks
`x86_64-apple-macos15.0` or `arm64-apple-macos15.0` from `uname -m`. Arm64
keeps historical paths (`build/full`, `scratch/mrroot_full`). x86_64 writes
`build/full-x86_64`, `scratch/mrroot_full-x86_64`,
`build/swiftui-guest-x86_64`. Swift module files are
`${ARCH}-apple-macos.swiftmodule`. `llvm-otool -hv` is graded with
`$OTOOL_CPU` (ARM64 / X86_64), not a weakened check.

Wired into `full/scripts/build_full.sh`, `full/frameworks/build_core_guest_package.sh`,
`full/swiftui/build_focus_{widget,onboarding,package}_guest.sh`,
`full/xcodeplan/build_and_run_reminder_scene_guest.sh`. The core-package
validators (`core_package_manifest.py`, `core_guest_package.py`) require the
**host** triple rather than a hardcoded arm64 one; the check is the same
shape.

`foundation-macho/scripts/guest_arch.inc` is a third number (link macos13,
compile macos15) and is sourced by the ud_guest link/score/slice/overlay
scripts.

### 5.3 libobjc (phase-2 prerequisite; also unblocks the `objc` fixture)

`build_objc4.sh` assembles `objc-msg-x86_64.s` and skips the arm64-only
