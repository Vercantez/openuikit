# ---------------------------------------------------------------------------
# THE FUTEX PROBLEM -- the item behind the cap, and the one that matters most
# ---------------------------------------------------------------------------
# src/shims/lock.c:498
#
#     return (int)syscall(SYS_futex, uaddr, op | opflags, val, timeout,
#                         uaddr2, val3);
#
# SEVEN ARGUMENTS THROUGH THE VARIADIC MULTIPLEXER, on libdispatch's core
# locking path -- every lock, every thread event. syscall() is precisely what
# machorun has said it will not forward, and it is right to refuse: Darwin's
# arm64 ABI puts variadic arguments on the stack and AAPCS64 puts the first
# eight in registers, so a forward reads six garbage values, one of which is a
# pointer it then writes through.
#
# TURNING FUTEX OFF IS NOT THE ANSWER, AND I CHECKED RATHER THAN ASSUMED.
# HAVE_FUTEX=0 looked attractive because the #else branch of the thread-event
# paths falls through to _dispatch_sema4_*, our own pthread semaphore backend
# from patch 4, already built and verified 4/4 on both platforms. Building it
# fails 6 TUs with "define _dispatch_lock encoding scheme for your platform":
# lock.h couples the lock-WORD ENCODING to the same flag as the futex SYSCALL.
# It is not a config switch, it is a platform port.
#
# So the ask is narrow: A NON-VARIADIC futex ENTRY POINT in libSystem, six
# fixed arguments --
#
#     int futex(uint32_t *uaddr, int op, uint32_t val,
#               const struct timespec *timeout, uint32_t *uaddr2,
#               uint32_t val3);
#
# -- plus a one-line patch here pointing _dispatch_futex at it instead of at
# syscall(). Non-variadic means no ABI hazard at all. Same shape as the gettid
# patch already in dispatch_patches.py, which replaced syscall(SYS_gettid) with
# a direct gettid() call for exactly this reason -- that patch is why `syscall`
# does not appear from queue.c. lock.c was never looked at, because its symbol
# sat behind the cap.
#

# ---------------------------------------------------------------------------
# WHAT ACTUALLY UNBLOCKED event_epoll.c, AND IT WAS OURS
# ---------------------------------------------------------------------------
# It was reported as blocked on libSystem lacking `sigaction`. libSystem does
# now export _sigaction, but that was never the whole story and the last piece
# was self-inflicted:
#
#   machorun's sdk/usr/include/signal.h is Apple's real 132-line header and
#   HAS ALWAYS declared sigaction() at line 87. swiftcore-macho's clean-room
#   sdk/libc/signal.h -- 62 lines, written when machorun's SDK carried no
#   signal.h -- was copied over it by an unconditional `cp -f` in stage_sdk.sh.
#   Ours is a strict SUBSET. It declared signal, raise, the sigset_t inlines
#   and sigsuspend, and omitted sigaction. The declaration was hidden by us.
#
# A shadowing copy cannot fail. It silently produces a sysroot smaller than the
# one it was built from, and every resulting error points at the consumer. Both
# stage_sdk.sh copies now REFUSE to overwrite an existing header instead, and
# sdk/libc/signal.h is deleted -- verified first by compiling a probe that uses
# the entire surface ours declared against machorun's header alone.
#
# This is the umbrella-shadows-reexport shape again: the wrong definition wins
# because it is applied last, not because it is better.
#
# Two more gaps behind it, both in our Linux-ABI overlay, both now fixed:
#   SIOCOUTQ        our linux/sockios.h defined SIOCINQ and not SIOCOUTQ, while
#                   event_epoll.c:532 uses `writer ? SIOCOUTQ : SIOCINQ`. Half
#                   a family. Measured 0x5411 on the host.
#   CLOCK_BOOTTIME  see the clock note below -- the one that mattered.
#
# ---------------------------------------------------------------------------
# THE CLOCK BUG THE COMPILER WOULD NOT HAVE CAUGHT
# ---------------------------------------------------------------------------
# event_epoll.c hands three clock ids to timerfd_create, a LINUX call:
#
#     clock              Darwin   Linux
#     CLOCK_REALTIME       0        0     agrees
#     CLOCK_MONOTONIC      6        1     DOES NOT AGREE
#     CLOCK_BOOTTIME    absent      7     absent on Darwin
#
# Only CLOCK_BOOTTIME is a compile error. Adding it -- the single thing the
# compiler asked for -- makes the file build and leaves CLOCK_MONOTONIC passing
# Darwin's 6 to Linux, where 6 is CLOCK_REALTIME_ALARM. Every
# DISPATCH_CLOCK_UPTIME timer would then fail with EPERM (that clock wants
# CAP_WAKE_ALARM) or, given the capability, quietly become a wall-clock alarm.
#
# THE COMPILER OBJECTS TO THE ABSENT CONSTANT AND NEVER TO THE PRESENT-BUT-
# WRONG ONE. Fixed as dispatch patch 14 with explicit TFD_CLOCK_* names, values
# measured on both sides, and a _Static_assert pinning the Darwin side so the
# table fails loudly if the SDK ever changes.
#
