## Probe recipe

`Tools/oracle2/collectioncontrollerprobe/main.swift`, one file, no Xcode
project. From `uikit/`:

```sh
SIM_DEVICE_SUFFIX=-uicollectionviewcontroller scripts/collection_controller_probe_sim.sh /tmp/cc
```

The script compiles with `xcrun swiftc -target arm64-apple-ios26.0-simulator`,
writes a minimal `Info.plist`, creates/boots an iPhone 16 / iOS 26.1 device
named `OpenUIKit-CollectionController<suffix>`, installs, launches with
`--console-pty`, and copies `Documents/collectioncontroller.json` out. The
probe rewrites the JSON after each phase so a crashing phase keeps the rows
before it; no phase crashed. The unedited transcript is carried as
`ios-26.1-iphone16.json`; its README lists every row.

Probe design notes: the coder rows build an EMPTY keyed archive
(`NSKeyedArchiver(requiringSecureCoding:false)` + `finishEncoding`) and
decode with `requiresSecureCoding = false`; the layout's nil-ness is read
through `value(forKey:)` because the Swift property is non-optional. The
round trip archives a programmatic controller with non-default preferences.
The gesture rows list recognizer class names for a movable data source
(`canMoveItemAt` + `moveItemAt`) with the preference on, off, and toggled
after load, detached and in a window.

## Limits, stated

- **Coder init substitutes a flow layout.** Apple's getter is nil after an
  empty archive and `collectionView` would trap on a nil layout; the port
  has no archive reader, so it follows `UICollectionView.init?(coder:)` and
  loads with a `UICollectionViewFlowLayout`. Archive keys (the two
  preferences Apple round-trips) are not decoded.
- **Reordering gesture is store-only.** The port's `UICollectionView` has no
  interactive movement and no `canMoveItemAt` / `moveItemAt` data-source
  members, so the measured in-window install rule is documented, not
  reproduced.
- **Only members the portable collection/scroll views call are declared
  open.** `shouldHighlightItemAt`, `didHighlightItemAt`, `shouldDeselectItemAt`,
  context-menu and multiple-selection members are not in the port's
  protocols; an app overriding them still fails to compile.
- **`override` inside an extension** (ios-oss line 348 overrides
  `willDisplay` in a class extension) requires an `@objc` base on Apple's
  compiler rules; the pure-Swift port cannot satisfy that on Linux. This is
  the route-(b) ObjC-shape wall already named for ios-oss in §9.6, not a
  UIKit-type gap, and it stays open.
- `flashScrollIndicators` hold time before the fade is unmeasured; nothing
  readable depends on it.
- `UIViewController.init?(coder:)` itself is still absent; the measured base
  row (`coder.empty.base`) is carried for whoever adds it.
